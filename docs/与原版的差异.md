## 为满足文件夹完整性要求保留的变化

- 先按结构与内容处理同级完整重复文件夹，再处理未受保护的叶子目录内部散文件。跨目录散文件仅报告，不按旧版全局逐文件隔离。
- 执行前重新枚举源与保留目录，检测新增、缺失和改变；不能只复核旧清单里的文件。
- 用同文件系统重命名隔离，不通过 shutil.move 跨盘复制后删除。
- 每个项目先记录 pending，完成后记录 done；异常保留运行锁，防止未经核查继续运行。
- 隔离位置增加运行编号和项目编号。原路径和目标位置均写入 CSV 与日志，避免历史同名冲突。
- 大小唯一或被类型筛选排除的文件不计算哈希，但仍记录在目录结构中。含未验证成员的文件夹不作为完整重复处理，避免连带隔离未选择的文件类型。

## V2 数据库增量架构说明 (选项 A 完整工程优先)

- **SQLite 索引缓存数据库 (`cleaner_vault.db`)**：采用 WAL 模式，记录已计算文件的相对路径、大小、修改时间与 SHA-256 哈希。中途中断或再次运行时，无需重复对未修改的文件进行物理硬盘哈希计算，二次扫描速度提升百倍。
- **分批安全隔离与判定**：遵循**选项 A 极保守原则**，优先处理经过完整结构与哈希校验的完整重复文件夹；只有确认整包完全相同的副本，才允许加入隔离队列。零散重复文件受叶子节点规则保护，留待后续处理，绝不拆散工程。
- **断点续扫与状态核对**：数据库同时记录 `isolation_journal`，每次启动时重核未完成项目，支持只读 `--audit` 日志审计。
- **自动跳过回收站**：自动过滤 Windows 系统回收站（`$RECYCLE.BIN` / `RECYCLER`）及卷保护目录，避免无用文件干扰判定。
